# Systematic Debugging in pretalx

This guide outlines a strict, scientific debugging methodology to resolve bugs within the **pretalx** system, comparing Python and JavaScript diagnostic tools.

---

## 🔬 The Six-Step Debugging Method

1.  **Reproduce:** Formulate a minimal, consistent reproduction script or test case. Never try to fix a bug you haven't reproduced first.
2.  **Narrow:** Isolate the issue to a specific layer (e.g. is it in the frontend Svelte drag-and-drop code, the django-scopes event permission middleware, or the ORM data persistence layer?).
3.  **Hypothesize:** Formulate 2-3 potential explanations based on the codebase structure.
4.  **Test Cheaply:** Validate your hypothesis using quick diagnostics (like printing SQL statements, inserting breakpoints, or running a single test case).
5.  **Fix Root Cause:** Avoid superficial "band-aid" patches (like swallowing exceptions). Fix the invariant.
6.  **Regression Test:** Write a dedicated unit test capturing this specific failure case.

---

## 🛠️ Diagnostics Toolkit

### Python / Django Tools
*   **The Interactive Debugger (`pdb` / `ipdb`):** Insert `breakpoint()` inside any Python method. This pauses execution and opens a live terminal to inspect local variables.
*   **SQL Query Inspection:** Print the raw SQL generated by any Django QuerySet:
    ```python
    queryset = Submission.objects.filter(is_featured=True)
    print(str(queryset.query)) # Outputs the raw SELECT statement!
    ```
*   **Django Management Shell:** Boot up the DB context in your terminal:
    ```powershell
    python src/manage.py shell --unsafe-disable-scopes
    ```
*   **Logging:** Inject quick logger statements:
    ```python
    import logging
    logger = logging.getLogger(__name__)
    logger.info(f"Loaded submission: {submission.code}")
    ```

### JS/TS Equivalent Tools
*   **Debugger Breakpoint:** Insert `debugger;` statement in JS files to pause browser execution.
*   **Chrome DevTools / Node Inspector:** Inspect active state objects and network requests.
*   **`console.log()`:** Inspect values in console.

## 🎯 Scenario walks

### Scenario 1: A speaker gets an HTTP 500 error when clicking "Accept Invitation"

#### 1. First Question: Is the bug in the CFP view layer or the domain signals layer?
*   **Check:** Open your browser's Network Tab. If the POST request returns `500 Internal Server Error`, look at your local Django terminal output log.

#### 2. Narrowing:
*   Insert a `breakpoint()` inside `accept_invitation` method inside `cfp/views/`.
*   Click the invitation button in your browser to hit the breakpoint.
*   Step through execution using `n` (next) and `s` (step into).

#### 3. Diagnostic Tool:
Use the pdb terminal to inspect variables:
```python
(Pdb) p request.user
(Pdb) p invitation.submission
```
If `invitation.submission` raises a `ScopeError`, you are attempting to run a database query outside the active event scope. Wrap the call inside an explicit event scope manager:
```python
from django_scopes import scope
with scope(event=invitation.event):
    # Safe query block!
    ...
```

### Scenario 2: The Svelte schedule editor widget is not reflecting room changes

#### 1. First Question: Is it a frontend state rendering bug or an API persistence failure?
*   **Check:** Look at the browser DevTools Network Tab when dragging a talk to a room.
*   If the PUT request to `/api/events/.../talks/` returns a `200 OK` but the Svelte UI resets, the bug is in the frontend Svelte store.
*   If the API returns a `400 Bad Request` or `403 Forbidden`, the bug resides in the API permissions view.

#### 2. Narrowing (API side):
*   Locate the endpoint serializer inside `src/pretalx/api/views/schedule.py`.
*   Print the serializer validation errors:
    ```python
    # Inside the view
    print(serializer.errors)
    ```

#### 3. Diagnostic Tool:
If it's an API validation failure, write a quick test case in `src/tests/api/` representing the payload to reproduce the issue cleanly and verify the fix without reloading the browser.
